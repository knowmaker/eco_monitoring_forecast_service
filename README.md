# Eco Monitoring Forecast Service

Отдельный сервис часового прогнозирования концентраций газов для карты концентраций.

## Модель

Сервис использует полуфизическую схему и один текущий артефакт с шестью моделями CatBoost, по одной для каждого газа. Физическая часть переносит и рассеивает поле концентраций, а модель соответствующего газа прогнозирует остаточную поправку для горизонтов 1–5 часов. Код газа выбирает модель внутри артефакта. В признаки входят:

- часовая история газов и скользящие статистики;
- координаты станции; идентификатор используется только для группировки данных и не передаётся модели;
- прогноз погоды Open-Meteo для исходного, транспортного и целевого часа;
- концентрации наветренных соседних станций, расстояния и оценка времени переноса;
- календарные признаки.
- горизонт прогноза в часах.

Посты Камшиловки 1, 2, 622 и 624 исключены из обучения и расчёта. Обучение в одной транзакции заменяет текущий артефакт в `public.current_model`. Реестр кандидатов, ручная активация и история версий отсутствуют.

## Временной контракт

При запуске Cron в `HH:50` используются данные с `data_cutoff = HH:00`. Пять целевых часов начинаются в `HH:00`, `(HH+1):00`, ..., `(HH+4):00`; второй из них является следующим полным календарным часом. Один запуск рассчитывает CO, NO, NO2, O3, SO2 и H2S для всех станций, имеющих измерение за последний завершённый час, и после завершения останавливается.

## Установка и БД

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
psql $env:DATABASE_URL -f forecast_schema.sql
```

Все таблицы сервиса создаются в общей схеме `public`.

## Подготовка, обучение и прогноз

```powershell
python -m app.features.hourly_gas --full
python -m app.features.weather_features --history
python -m app.training.train
python -m app.worker
```

`app.training.train` проверяет модель на более позднем временном интервале, затем обучает шесть моделей на доступной истории и заменяет текущий артефакт. Схема таблиц при этом не меняется.

Для однократного заполнения пространственной сетки по уже сохранённым наблюдениям и прогнозам:

```powershell
python -m app.inference.concentration_grid --backfill
```

Команда Railway Cron:

```powershell
python -m app.worker --train-if-missing
```

Для сервиса в Railway задаётся расписание `50 * * * *` в UTC. Флаг обучает модель только при её отсутствии или несовместимом формате. Каждый запуск проверяет кадры за последние 24 часа. Если анализ или один из пяти прогнозных часов отсутствует при наличии соответствующего часового агрегата, команда пересчитывает все запуски от первого пропуска до текущего расчётного часа. Это восстанавливает не только отдельный кадр, но и последовательный перенос поля после него. Глубина проверки настраивается через `FORECAST_CATCHUP_HOURS` в диапазоне от 1 до 168 часов.

После каждого почасового прогноза worker строит сетку концентраций с ячейкой 500 × 500 метров. Наблюдения корректируют фоновое поле методом анизотропной оптимальной интерполяции в радиусе до 10 км: вдоль ветра влияние сохраняется дольше, чем поперёк него. Готовый часовой агрегат Мосэкомониторинга учитывается в интерполяции как три измерения без изменения сохранённого `samples_count`. Отдельные пространственные кластеры не создаются. Поле прошедшего часа последовательно переносится на пять целевых часов и на каждом часу корректируется предсказаниями модели соответствующего газа. На каждом коротком шаге консервативная схема конечных объёмов переносит концентрацию через границы ячеек по локальному ветру и рассеивает её в соседние ячейки; размер шага выбирается по скорости ветра и диффузии. Газоспецифическое ослабление и вымывание осадками применяются на тех же шагах. Ошибка предыдущего прогноза дополнительно распространяется против ветра на предыдущий час и участвует в следующем прямом расчёте. Достоверность перенесённых ячеек каждый час умножается на 0,65; ячейки с `confidence < 0,02` удаляются. Сжатые кадры хранятся 24 часа.

Отрицательные концентрации для обучения, физического расчёта и карты концентраций ограничиваются нулём, а не переводятся в модуль: измерительный шум не должен создавать дополнительную массу газа. Исходные записи `public.gas_sensors` не изменяются.

Каждый кадр сохраняется одной сжатой записью `BYTEA` в PostgreSQL. Артефакт модели также хранится в `BYTEA`. Дополнительное файловое или объектное хранилище и Railway volume не используются.
