# Eco Monitoring Forecast Service

Отдельный сервис часового прогнозирования концентраций газов для карты концентраций.

## Модель

Сервис использует одну полуфизическую модель и один текущий артефакт CatBoost, обученный на данных всех газов и станций. Физическая часть переносит и рассеивает поле концентраций, а CatBoost прогнозирует остаточную поправку. Код газа передаётся CatBoost как категориальный признак. В признаки входят:

- часовая история газов и скользящие статистики;
- координаты станции; идентификатор используется только для группировки данных и не передаётся модели;
- прогноз погоды Open-Meteo для исходного, транспортного и целевого часа;
- концентрации наветренных соседних станций, расстояния и оценка времени переноса;
- календарные признаки.

Обучение в одной транзакции заменяет текущий артефакт в `public.current_model`. Реестр кандидатов, ручная активация, отдельные модели по газам и история версий отсутствуют.

## Временной контракт

При запуске Cron в `HH:50` используются данные с `data_cutoff = HH:00`, а прогноз строится для следующего полного календарного часа `(HH+1):00–(HH+2):00`. Один запуск рассчитывает CO, NO, NO2, O3, SO2 и H2S для всех станций, имеющих достаточную локальную историю, и после завершения останавливается.

## Установка и БД

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
psql $env:DATABASE_URL -f forecast_schema.sql
```

Все таблицы сервиса создаются в общей схеме `public`.

## Подготовка, обучение и прогноз

```powershell
python -m app.features.hourly_gas --full
python -m app.features.weather_features --history
python -m app.training.train
python -m app.training.evaluate
python -m app.worker
```

`app.training.evaluate` выполняет несколько последовательных временных проверок и отдельные проверки с исключением каждой станции из обучающей выборки. Команда не заменяет текущую модель.

Для однократного заполнения пространственной сетки по уже сохранённым наблюдениям и прогнозам:

```powershell
python -m app.inference.concentration_grid --backfill
```

Команда Railway Cron:

```powershell
python -m app.worker --train-if-missing
```

Для сервиса в Railway задаётся расписание `50 * * * *` в UTC. Флаг обучает модель только при её отсутствии или несовместимом формате. Каждый запуск проверяет кадры за последние 72 часа. Если наблюдаемый или прогнозный кадр отсутствует при наличии соответствующего часового агрегата, команда пересчитывает все запуски от первого пропуска до текущего расчётного часа. Это восстанавливает не только отдельный кадр, но и последовательный перенос поля после него. Глубина проверки настраивается через `FORECAST_CATCHUP_HOURS` в диапазоне от 1 до 168 часов.

После каждого почасового прогноза worker строит сетку концентраций с ячейкой 500 × 500 метров. Наблюдения корректируют фоновое поле методом анизотропной оптимальной интерполяции в радиусе до 10 км: вдоль ветра влияние сохраняется дольше, чем поперёк него. Отдельные пространственные кластеры не создаются. Всё сохранённое поле переносится на расстояние `скорость ветра × время` с автоматически выбранным числом шагов, после чего применяются рассеивание, газоспецифическое ослабление, осадки и поправка CatBoost. Ошибка предыдущего прогноза дополнительно распространяется против ветра на предыдущий час и участвует в следующем прямом расчёте. Достоверность перенесённых ячеек каждый час умножается на 0,65; ячейки с `confidence < 0,04` или пренебрежимо малой концентрацией удаляются. Сжатые кадры хранятся 72 часа.

Отрицательные концентрации для обучения, физического расчёта и карты концентраций ограничиваются нулём, а не переводятся в модуль: измерительный шум не должен создавать дополнительную массу газа. Исходные записи `public.gas_sensors` не изменяются.

Каждый кадр сохраняется одной сжатой записью `BYTEA` в PostgreSQL. Артефакт модели также хранится в `BYTEA`. Дополнительное файловое или объектное хранилище и Railway volume не используются.
