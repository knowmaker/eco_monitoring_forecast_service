# Реализация прогнозирования для тепловой карты

## Основные решения

- Используется один тип пространственной модели; пользователь не выбирает алгоритм.
- Одна общая полуфизическая модель работает со всеми газами и станциями; газ является категориальным признаком CatBoost.
- Существует только один текущий артефакт в поле `BYTEA` таблицы `public.current_model`.
- Повторное обучение заменяет единственную строку `public.current_model` в одной транзакции.
- Один почасовой запуск формирует прогнозы всех газов для всех доступных станций.
- Одноразовый cron-процесс при запуске проверяет последние 72 часа, последовательно восстанавливает пропущенные прогнозы и кадры, затем завершается.
- Отрицательные предсказанные концентрации ограничиваются нулём.

## Данные

Сырые газовые измерения проходят причинную медиану из трёх значений и затем усредняются по часу. Погодные признаки поступают только из Open-Meteo: ветер на 10 и 100 м, высота пограничного слоя, порывы, температура, влажность, давление, осадки, облачность и солнечная радиация. Пространственные признаки рассчитываются по наветренным соседям с учётом расстояния, направления и скорости ветра, а также приближённого времени переноса.

Для каждой станции сначала рассчитывается прозрачный физический baseline. CatBoost обучается не на самой концентрации, а на остатке `факт − physical_baseline`. Итоговый прогноз равен физическому baseline плюс поправка CatBoost.

Отсутствие подходящего соседа не блокирует прогноз отдельной станции: пространственные значения остаются пустыми, а модель использует локальную историю, погоду, координаты и календарные признаки.

## Таблицы

- `public.gas_hourly_features` — сохранённые часовые измерения;
- `public.external_weather_hourly` — историческая и оперативная погода Open-Meteo;
- `public.current_model` — единственная текущая модель вместе с сериализованным артефактом;
- `public.gas_predictions` — результаты по станции, газу и целевому часу;
- `public.gas_concentration_frames` — наблюдаемые и прогнозные поля, по одному сжатому `BYTEA`-кадру на газ и час.

В таблицах нет уровня модели, номера версии или статуса кандидата.

## Карта концентраций

После расчёта значений на станциях сервис строит пространственную сетку с ячейкой 500 × 500 метров и начальным радиусом покрытия 1500 метров. Максимальный локальный перенос поля за час ограничен 1500 метрами. Область прошедшего часа объединяет круги текущих наблюдений с полем ранее построенного прогноза на этот час. На следующем шаге переносится вся получившаяся область, поэтому охват может постепенно расширяться по направлению ветра. Каждый час выполняются четыре стадии:

1. предыдущий прогноз корректируется новыми измерениями станций;
2. поле переносится по ветру методом переноса ячеек;
3. применяются турбулентная диффузия, газоспецифическое ослабление и вымывание осадками;
4. физическое поле корректируется результатами CatBoost в координатах станций.

Для каждой прогнозной ячейки раздельно сохраняются `physical_forecast`, `correction_value` и итоговое `value`. Достоверность перенесённой части поля каждый час уменьшается до 65% предыдущего значения. Ячейки с `confidence < 0,04` или концентрацией менее `0,000001` удаляются, кроме актуальной области наблюдений вокруг станций. Поэтому старый след постепенно исчезает, а карта не заполняется бессрочно. Одиночная станция получает собственную область, но не соединяется искусственным полем с удалёнными станциями. Кадры старше 72 часов автоматически удаляются.

Отрицательные газовые значения ограничиваются нулём. Модуль не используется, поскольку он превращал бы отрицательный измерительный шум в дополнительную массу загрязнителя. Исходные записи датчиков при этом не изменяются.

Прогноз для станции и газа рассчитывается только тогда, когда за последний завершённый час присутствует `filtered_hourly_mean` этого газа. Более старые пропуски в истории допустимы и могут обрабатываться моделью как отсутствующие признаки.

Интерфейс запрашивает временную ленту по газу. Для прошлого часа API выбирает сохранённый наблюдаемый кадр, для будущего — прогнозный. Содержимое кадра хранится одним сжатым NumPy-массивом в поле `BYTEA`. FastAPI формирует из кадра PNG-тайлы, поэтому MapLibre загружает только видимую часть поля и не получает массив ячеек в JSON.
