# Реализация прогнозирования для тепловой карты

## Основные решения

- Используется один тип пространственной модели; пользователь не выбирает алгоритм.
- Полуфизическая схема использует шесть моделей CatBoost, по одной для каждого газа; горизонт 1–5 часов входит в признаки каждой модели.
- Существует только один текущий артефакт с шестью моделями в поле `BYTEA` таблицы `public.current_model`.
- Повторное обучение заменяет единственную строку `public.current_model` в одной транзакции.
- Один почасовой запуск формирует по пять прогнозов каждого газа для всех доступных станций.
- Одноразовый cron-процесс при запуске проверяет последние 24 часа, последовательно восстанавливает пропущенные прогнозы и кадры, затем завершается.
- Отрицательные предсказанные концентрации ограничиваются нулём.

## Данные

Сырые газовые измерения проходят причинную медиану из трёх значений и затем усредняются по часу. Погодные признаки поступают только из Open-Meteo: ветер на 10 и 100 м, высота пограничного слоя, порывы, температура, влажность, давление, осадки, облачность и солнечная радиация. Пространственные признаки рассчитываются по наветренным соседям с учётом расстояния, направления и скорости ветра, а также приближённого времени переноса.

Для каждой станции сначала рассчитывается прозрачный физический baseline. CatBoost обучается не на самой концентрации, а на остатке `факт − physical_baseline`. Итоговый прогноз равен физическому baseline плюс поправка CatBoost.

Отсутствие подходящего соседа не блокирует прогноз отдельной станции: пространственные значения остаются пустыми, а модель использует локальную историю, погоду, координаты и календарные признаки.

Посты Камшиловки 1, 2, 622 и 624 исключены из обучения и оперативного расчёта. Для прогноза используется погода соответствующего целевого часа.

## Таблицы

- `public.gas_hourly_features` — сохранённые часовые измерения;
- `public.external_weather_hourly` — историческая и оперативная погода Open-Meteo;
- `public.current_model` — один текущий сериализованный артефакт с шестью моделями;
- `public.gas_predictions` — результаты по станции, газу и целевому часу;
- `public.gas_concentration_frames` — анализы прошедших часов и прогнозные поля, по одному сжатому `BYTEA`-кадру на газ и час.

В таблицах нет уровня модели, номера версии или статуса кандидата.

## Карта концентраций

После расчёта значений на станциях сервис строит единую пространственную сетку с ячейкой 500 × 500 метров. Фоновый прогноз и наблюдения объединяются анизотропной оптимальной интерполяцией с максимальным радиусом влияния 10 км. Ковариация зависит от локального ветра, уверенности фонового поля и качества часового наблюдения. Отдельные кластеры и фиксированные буферы не используются. Каждый расчёт выполняет пять стадий:

1. предыдущий прогноз корректируется новыми измерениями станций;
2. невязка прогноза распространяется против локального ветра на предыдущий час;
3. всё поле последовательно переносится на пять целевых часов консервативной схемой конечных объёмов с локальным ветром и ограничением потока; число шагов определяется скоростью ветра, диффузией и размером ячейки;
4. на каждом шаге применяются горизонтальная диффузия, газоспецифическое ослабление и вымывание осадками;
5. на каждом целевом часу остаточная поправка модели соответствующего газа распространяется по полю той же оптимальной интерполяцией.

Для каждой прогнозной ячейки раздельно сохраняются `physical_forecast`, `correction_value` и итоговое `value`. Также сохраняются локальные компоненты ветра `wind_u/wind_v` и уверенность анализа. Достоверность перенесённой части поля каждый час уменьшается до 65% предыдущего значения. Ячейки с `confidence < 0,02` удаляются; вне зоны станций удаляются и пренебрежимо малые концентрации. Кадры старше 24 часов автоматически удаляются.

Отрицательные газовые значения ограничиваются нулём. Модуль не используется, поскольку он превращал бы отрицательный измерительный шум в дополнительную массу загрязнителя. Исходные записи датчиков при этом не изменяются.

Прогноз для станции и газа рассчитывается только тогда, когда за последний завершённый час присутствует `filtered_hourly_mean` этого газа. Более старые пропуски в истории допустимы и могут обрабатываться моделью как отсутствующие признаки.

Интерфейс запрашивает временную ленту по газу. Для прошлого часа API выбирает анализ, для текущего и четырёх последующих — прогнозные кадры. Содержимое кадра хранится одним сжатым NumPy-массивом в поле `BYTEA`. FastAPI формирует из кадра PNG-тайлы, поэтому MapLibre загружает только видимую часть поля и не получает массив ячеек в JSON.
