# Реализация прогнозирования для тепловой карты

## Основные решения

- Используется один тип пространственной модели; пользователь не выбирает алгоритм.
- Одна общая CatBoost-модель обучается на всех газах и станциях; газ является категориальным признаком.
- Существует только один текущий артефакт `artifacts/current/gas_forecast.joblib`.
- Повторное обучение сразу заменяет файл и единственную строку `public.current_model`.
- Один почасовой запуск формирует прогнозы всех газов для всех доступных станций.
- Отрицательные предсказанные концентрации ограничиваются нулём.

## Данные

Сырые газовые измерения проходят причинную медиану из трёх значений и затем усредняются по часу. Погодные признаки поступают только из Open-Meteo. Пространственные признаки рассчитываются по наветренным соседям с учётом расстояния, направления и скорости ветра, а также приближённого времени переноса.

Отсутствие подходящего соседа не блокирует прогноз отдельной станции: пространственные значения остаются пустыми, а модель использует локальную историю, погоду, координаты и календарные признаки.

## Таблицы

- `public.gas_hourly_features` — сохранённые часовые измерения;
- `public.external_weather_hourly` — историческая и оперативная погода Open-Meteo;
- `public.current_model` — единственная текущая модель;
- `public.gas_predictions` — результаты по станции, газу и целевому часу.

В таблицах нет уровня модели, номера версии или статуса кандидата.

## Тепловая карта

Интерфейс запрашивает временную ленту по газу. Для часа в прошлом API возвращает `filtered_hourly_mean` из сохранённых наблюдений, для будущего часа — пакетный прогноз. Каждый кадр содержит координаты, название станции и концентрацию, поэтому MapLibre строит общий тепловой слой без привязки API-маршрута к конкретному посту.
