# Реализация прогнозирования для тепловой карты

## Основные решения

- Используется один тип пространственной модели; пользователь не выбирает алгоритм.
- Одна общая CatBoost-модель обучается на всех газах и станциях; газ является категориальным признаком.
- Существует только один текущий артефакт `artifacts/current/gas_forecast.joblib`.
- Повторное обучение сразу заменяет файл и единственную строку `public.current_model`.
- Один почасовой запуск формирует прогнозы всех газов для всех доступных станций.
- Отрицательные предсказанные концентрации ограничиваются нулём.

## Данные

Сырые газовые измерения проходят причинную медиану из трёх значений и затем усредняются по часу. Погодные признаки поступают только из Open-Meteo. Пространственные признаки рассчитываются по наветренным соседям с учётом расстояния, направления и скорости ветра, а также приближённого времени переноса.

Отсутствие подходящего соседа не блокирует прогноз отдельной станции: пространственные значения остаются пустыми, а модель использует локальную историю, погоду, координаты и календарные признаки.

## Таблицы

- `public.gas_hourly_features` — сохранённые часовые измерения;
- `public.external_weather_hourly` — историческая и оперативная погода Open-Meteo;
- `public.current_model` — единственная текущая модель;
- `public.gas_predictions` — результаты по станции, газу и целевому часу;
- `public.gas_concentration_grid` — наблюдаемое и прогнозное поле концентраций по ячейкам карты.

В таблицах нет уровня модели, номера версии или статуса кандидата.

## Тепловая карта

После расчёта значений на станциях сервис строит пространственную сетку с ячейкой 100 × 100 метров и буфером 1000 метров. Для прогноза учитываются расстояния, ветер, перенос текущего наблюдаемого поля и прогнозные значения станций. Если актуального наблюдаемого поля нет, для переноса используются сами прогнозные значения. Значения вдали от станций получают меньшую уверенность. Одиночная станция получает собственную область, но не соединяется искусственным полем с удалёнными станциями. Кадры старше 14 дней автоматически удаляются.

Газовые значения перед построением часовых признаков переводятся в модуль. То же правило дополнительно применяется при чтении обучающей выборки и построении сетки, поэтому отрицательные концентрации не используются ни как признаки, ни как целевые значения, ни при визуализации.

Прогноз для станции и газа рассчитывается только тогда, когда за последний завершённый час присутствует `filtered_hourly_mean` этого газа. Более старые пропуски в истории допустимы и могут обрабатываться моделью как отсутствующие признаки.

Интерфейс запрашивает временную ленту по газу. Для прошлого часа API возвращает сохранённую наблюдаемую сетку, для будущего — прогнозную. Каждый кадр содержит прямоугольные границы ячеек, концентрацию и уверенность, поэтому MapLibre рисует сплошные полигоны без кругов вокруг станций.
